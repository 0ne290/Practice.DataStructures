# Списки на массивах: общий API и CircularArrayList

## Модель и статус

`ArrayList<T>` и `CircularArrayList<T>` — расширяемые индексируемые списки
на встроенных массивах `T[]`. Они сохраняют логический порядок элементов
и предоставляют одинаковый основной позиционный API. Различается организация
хранения и стоимость операций. `CircularArrayList<T>` допускает продолжение
логической последовательности через конец внутреннего массива к его началу.
Публичные индексы остаются обычными индексами списка.

Документ фиксирует согласованный целевой API. В текущем Core `ArrayList<T>`
поддерживает `Insert`; расширение прошло оба этапа ревью.
`CircularArrayList<T>` ещё не реализован и выполняется автором
в отдельном учебном этапе. Этот документ не разрешает нейросети менять Core.
Под стандартным списком на массиве здесь понимается собственный `ArrayList<T>`
практикума, а не весь API библиотечного `System.Collections.Generic.List<T>`.

## Общий позиционный API

Целевой общий API обоих списков содержит следующие публичные члены;
это описание контракта,
а не требование вводить новый общий интерфейс C#:

```csharp
int Count { get; }
int Capacity { get; }

T this[int index] { get; set; }

void Add(T item);
void Insert(int index, T item);
void RemoveAt(int index);

int IndexOf(IndexedPredicate<T> indexedPredicate);
bool Contains(IndexedPredicate<T> indexedPredicate);

void Clear();
```

Целевой профиль предусматривает `IEnumerable<T>` и конструкторы без параметров
и с параметром `int capacity`. Для совместимости с текущим `ArrayList<T>`
начальная вместимость по умолчанию — 8, явно заданная — не меньше единицы.
Пустота определяется через `Count == 0`.

| Член | Наблюдаемое поведение |
| --- | --- |
| `Count` | Количество элементов логической последовательности |
| `Capacity` | Вместимость внутреннего хранилища; свободные ячейки не являются элементами списка |
| Индексатор | Чтение или замена существующего элемента по индексу `[0, Count)` |
| `Add(item)` | Добавление в конец; по результату соответствует `Insert(Count, item)` |
| `Insert(index, item)` | Вставка перед указанной позицией с сохранением порядка; допустимы позиции `[0, Count]`, включая добавление после последнего элемента |
| `RemoveAt(index)` | Удаление существующего элемента по индексу `[0, Count)` с сохранением порядка остальных |
| `IndexOf` | Индекс первого совпадения с условием либо `-1`; проверка в логическом порядке от начала |
| `Contains` | Наличие элемента, удовлетворяющего условию |
| `Clear` | Удаление всех элементов с сохранением вместимости |
| Перебор | От первого логического элемента к последнему, без удаления |

Индексы не оборачиваются. Недопустимый индекс и недопустимая начальная
вместимость приводят к `ArgumentOutOfRangeException`. Допускаются дубликаты
и значения по умолчанию, включая допустимые для типа `null`.
Условие получает элемент и его текущую логическую позицию.

Для общих существующих операций сохраняется принятый контракт `ArrayList<T>`,
описанный в его XML-комментариях и [тестовой лаборатории](testing.md).
Условие поиска должно быть ненулевым; защитная проверка этого предусловия
не выполняется. Успешные изменения и каждый `Clear`, включая очистку пустого
списка, инвалидируют перечислители. Чтение и операции, отклонённые из-за
недопустимого индекса, сохраняют их работоспособность.
Успешный `Insert` также инвалидирует перечислители.
Общий контракт не ослабляется при добавлении второй реализации;
итоговые XML-комментарии оформляются после ревью.

## Дополнение CircularArrayList: чтение концов

`CircularArrayList<T>` дополнительно предоставляет два свойства только для чтения:

```csharp
T First { get; }
T Last { get; }
```

`First` возвращает первый логический элемент, `Last` — последний, без удаления
и изменения состояния. Это значения типа `T`, а не узлы или курсоры.
На пустом списке оба свойства выбрасывают `InvalidOperationException`.
Чтение выполняется за O(1) и не инвалидирует перечислители.

Целевой основной API зеркально совпадает с API `ArrayList<T>`; свойства концов
являются дополнением `CircularArrayList<T>`. По результату это удобные формы
чтения `[0]` и `[Count - 1]` у непустого списка. Они не означают принципиально
новой возможности; их польза — в явном обозначении выбранного конца.
Остальные общие операции имеют одинаковые имена и контракты.

Добавление и удаление остаются позиционными: `Insert` / `Add` и `RemoveAt`.
Операции очереди, специальные операции извлечения с концов и отдельный набор
двусторонних команд в API списка не вводятся. Курсоры и операции управления
физическим размещением в согласованный профиль не входят.

## Политика вместимости и сложность

Оба списка автоматически расширяют вместимость с сохранением всех элементов.
Удаление и очистка сохраняют вместимость; автоматическое сжатие не требуется.
Гарантии сложности ниже — требования к реализациям, а не описание алгоритмов.

| Операция | ArrayList | CircularArrayList |
| --- | --- | --- |
| Количество, вместимость, чтение и замена по индексу | O(1) | O(1) |
| `First` / `Last` | Доступ к тем же элементам через индексатор за O(1) | O(1) |
| Добавление в конец | Амортизированное O(1) | Амортизированное O(1) |
| Вставка в начало | O(n) в худшем случае | Амортизированное O(1) |
| Удаление первого элемента | O(n) в худшем случае | O(1) |
| Удаление последнего элемента | O(1) | O(1) |
| Вставка в позицию i без расширения хранилища | O(1 + n − i) | O(1 + min(i, n − i)) |
| Удаление позиции i | O(1 + n − 1 − i) | O(1 + min(i, n − 1 − i)) |
| Поиск, полный перебор, очистка | O(n) | O(n) |

Здесь n — количество элементов до операции. Стоимость поиска предполагает
постоянную стоимость условия. Отдельная вставка с расширением может занимать
O(n) у обоих списков. Преимущество `CircularArrayList<T>` — гарантии для начала
и позиций вблизи обоих концов; одинаковые асимптотические оценки не означают
одинаковые константы времени. Превосходство по времени для любых входов
не утверждается.

## Преемственность и порядок изучения

Порядок реализации закреплён в
[спецификации](specification.md#инженерное-расширение-раздела-4-два-подхода-к-реализации-структур-данных).

`ArrayQueue<T>` и `ArrayDeque<T>` используют собственный `CircularArrayList<T>`
через композицию. Очередь предоставляет FIFO-контракт, дек — доступ с обоих
концов; их обёртки скрывают полный индексный API списка. `LinkedQueue<T>`
использует собственный односвязный список, `LinkedDeque<T>` — двусвязный.
Роль списка самостоятельна: произвольный индексный доступ, замена, вставка,
удаление и поиск, а не только операции с концами.

Общий позиционный контракт обоих списков после двух этапов ревью проверяется
общими тестами. Свойства `First` / `Last`, организация хранения и специфические
инварианты проверяются отдельно. При расширении `ArrayList<T>` используется
его существующий Laboratory-сценарий; для `CircularArrayList<T>` при начале
реализации создаётся ровно один авторский полигон по [правилам лаборатории](testing.md).
До окончания обоих этапов ревью готовая демонстрация и новые контрактные тесты
за автора не пишутся.
Согласование целевого профиля и включение в план не означают начало реализации:
полигон нового упражнения создаётся при переходе к нему.
