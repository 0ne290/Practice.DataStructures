# Ревью ArrayStack<T>

## Функциональная корректность и надёжность

Ошибок в реализации операций не обнаружено. Вершина соответствует последнему
элементу DynamicArray; Pop читает и удаляет именно его, Peek сохраняет состояние.
Count и IsEmpty вычисляются по фактическому состоянию хранилища. Очистка и
освобождение ячеек при удалении делегированы ранее проверенному DynamicArray.
Извлечение последнего элемента не выполняет сдвиги и занимает O(1).

Оба TODO выполнены по явному запросу автора: Pop и Peek для пустого стека
выбрасывают InvalidOperationException с сообщением «Stack is empty.».
Проверка пустоты предшествует изменению состояния.

## Архитектура и API

Отдельное ревью завершено без замечаний. Композиция с DynamicArray сохраняет
закрытое хранилище и ограничивает доступ операциями стека. Повторной реализации
роста массива и удаления нет. Публичный API соответствует постановке;
общие интерфейсы и дополнительные операции сейчас не требуются.
Peek и Pop выполняются за O(1), Push — амортизированное O(1), Clear — O(n).

XML-комментарии оформляют принятое поведение. Реализация автора сохранена,
кроме двух явно порученных замен исключений.

## Проверки

Обычные тесты находятся в Collections/Stack/ArrayStackTests.cs: создание,
порядок LIFO при росте массива, Peek без удаления, ошибки пустого стека,
очистка, повторное использование, null, дубликаты и ссылочная идентичность.
Смешанные операции сравниваются со Stack<int> после каждого шага для двух
фиксированных seed, в конце сравниваются все оставшиеся элементы.

Единственный Laboratory-сценарий заменён демонстрацией с новым случайным seed
по умолчанию и повтором через DATASTRUCTURES_LAB_SEED.

Restore в locked mode, сборка Release, проверка форматирования и 305 обычных
тестов (14 новых проверок стека) прошли. Демонстрация выполнена с новым seed
539176574 и с заданным seed 12345. Проверки запускались через терминал Rider;
каталог пакетов соответствует пользовательскому NuGet-кэшу.
Rider inspections выполнены: оставлены подсказки о выделениях памяти объектов,
строк и делегатов и о boxing в Assert.Throws. Они ожидаемы для этих проверок;
тесты не измеряют аллокации и не сохраняют делегаты за пределами запуска.

## Расширение: foreach

По явному запросу автора добавлены IEnumerable<T> и необобщённый IEnumerable.
Проверка корректности: обход идёт от вершины к основанию без удаления и копии;
версия фиксируется при получении перечислителя. Push, успешный Pop и каждый
Clear инвалидируют MoveNext и Current. Чтение и отклонённые операции сохраняют
перечислитель. Проверены пустой стек, null, дубликаты, вложенные и повторные
обходы, ранний выход, Current, Reset, Dispose и изменения до, во время и после
обхода. Отдельная проверка архитектуры: закрытый перечислитель хранит собственную
позицию, не раскрывает хранилище и не меняет асимптотику операций стека.
Добавлены 19 обычных проверок; всего проходят 324 теста. Restore в locked mode,
сборка Release и проверка форматирования прошли. Существующая демонстрация
дополнена foreach и обнаружением изменения, отдельный Laboratory не создавался.
Демонстрация прошла с новым случайным seed и с seed 12345. Rider inspections
выполнены: явный Dispose внутри using оставлен для проверки состояния после
освобождения и повторного Dispose; приведение к IEnumerable проверяет именно
необобщённый интерфейс. Циклы foreach сохранены как предмет проверки.
Подсказки о форме return, method group и выделениях памяти не влияют на контракт.

## Общие проверки парных стеков

После завершения LinkedStack проверки операций и перечисления перенесены
в StackContractTests и выполняются для обеих реализаций через отдельные
классы ArrayStackTests и LinkedStackTests. Добавлены проверки изменений после
Dispose и Current пустого перечислителя. Необобщённый обход проверяется прямым
foreach через IEnumerable. Демонстрация остаётся одним Laboratory-фактом
и показывает оба стека на одинаковых данных. Подробности: [LinkedStack](linked-stack.md).
