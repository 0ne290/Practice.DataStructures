# Ревью LinkedDeque<T>

## Функциональная корректность и надёжность

Первый этап завершён. В реализованных автором операциях добавления,
чтения, извлечения с обоих концов и очистки функциональных ошибок
не обнаружено. Проверены также используемые операции DoublyLinkedList<T>.
Изменения версии дека происходят после успешного изменения списка;
отклонённые операции на пустом деке сохраняют состояние и перечислители.
Проверка наличия курсора в PeekFront / PeekBack допускает null как значение
элемента. Добавление узла и создание нового поколения при Clear выполняют
необходимую аллокацию до изменения состояния списка.

По явному запросу автора выполнены три участка TODO Codex: оба входа
в перебор и частный перечислитель. Обход идёт от начала к концу без копии
содержимого; версия фиксируется при создании перечислителя. Успешные
PushFront, PushBack, PopFront, PopBack и каждый Clear инвалидируют обход.
MoveNext и оба Current обнаруживают изменение до начала, во время,
после конца обхода и после Dispose. Current вне элемента выбрасывает
InvalidOperationException. Dispose завершает обход, допускает повторный
вызов; при неизменном деке MoveNext после Dispose возвращает false.
Reset всегда выбрасывает NotSupportedException.

Временный диагностический запуск вне проектов сверил 60 000 смешанных
операций с LinkedList<int>: по 20 000 для seed 0, 12345 и 987654321.
После каждого шага сравнивались количество, пустота, последовательность
и доступные концы. Отдельно проверены шесть вариантов изменения в четырёх
состояниях перечислителя, включая изменение с сохранением Count;
очистка пустого дека; состояния обоих Current, Reset, повторный Dispose;
оба входа в перебор; независимые вложенные обходы; сохранение обхода при
чтении и отклонённых операциях; опустошение и повторное использование;
null, дубликаты, крайние значения int и ссылочная идентичность.
Все 324 099 диагностических проверок прошли.

Locked restore, сборка Release без предупреждений, проверка форматирования
и все 578 существующих обычных тестов прошли. Rider проверил LinkedDeque.cs:
отмечены только ожидаемые аллокации списка и перечислителя и возможный
boxing в необобщённом Current; исправлений по корректности не требуется.
Постоянные тесты и авторский Laboratory не изменялись.

## Архитектура, код и API

Отдельный второй этап завершён. Замечаний, требующих исправления,
по архитектуре, коду и публичному API не обнаружено.

Имя LinkedDeque<T> и имя файла согласованы со словарём: дек на связанных
узлах. PushFront / PushBack, PopFront / PopBack и PeekFront / PeekBack
явно обозначают выбранный конец и соответствуют наблюдаемому поведению.
Count, IsEmpty, Clear и IEnumerable<T> дополняют базовый профиль.
Публичные операции, сигнатуры, ошибки пустых операций, порядок обхода
и правила инвалидирования совместимы с ArrayDeque<T>. Индексатор,
поиск, обратный обход, публичные курсоры и Capacity для задачи не нужны.
Заранее заданного ограничения количества элементов нет.

Композиция с собственным DoublyLinkedList<T> соответствует постановке:
узлы, курсоры и расширенный API списка остаются скрытыми. Количество
не дублируется. Добавление, чтение и извлечение с обоих концов, Count
и IsEmpty имеют стоимость O(1); полный перебор — O(n), Clear — O(1).
PeekFront / PeekBack получают временный курсор за O(1), что добавляет
аллокацию, но не меняет асимптотику и не требует переделки готового списка.
Проверяется наличие курсора, а не ненулевое значение элемента.

Методы короткие, делегирование явно показывает выбранный конец,
ответственность хранилища и публичного контракта разделена. Собственная
версия дека меняется после успешной операции списка. Частный перечислитель
обходит список без копирования и добавляет проверку версии дека и состояние
Dispose: внутренний перечислитель списка сам по себе обход при Dispose
не завершает. Обёртка согласована с ArrayDeque<T> и готовыми очередями.
Её дополнительный объект и повторная проверка версии допустимы;
общая инфраструктура для небольших частных перечислителей не требуется.

Clear отсоединяет цепочку без обхода узлов. Старый перечислитель может
удерживать отсоединённые узлы, даже после Dispose, пока на него есть ссылка:
Dispose внутреннего перечислителя ничего не делает. Это свойство принятого
хранилища, а не нарушение корректности; его следует отразить в итоговых
XML-комментариях. Не обещать немедленное освобождение всех ссылок при Clear.

Согласованность имени, словаря, API и поведения проверена. XML-комментариев
для сверки пока нет; их отсутствие до финального оформления допустимо.
Повторная диагностика Rider выявила только ожидаемые аллокации списка
и перечислителя и возможный boxing в необобщённом Current.
Реализация, объявления и сигнатуры на втором этапе не менялись.

Оба этапа ревью завершены.

## Итоговое оформление

XML-комментарии оформлены и сверены со словарём, именами, публичным API
и принятым поведением. Описаны профиль дека, двусвязное хранение, отсутствие
заданного ограничения количества, сложность, ошибки, порядок и состояния
обхода. Отмечены временный курсор при чтении конца и возможное удержание
узлов старым перечислителем после Clear и Dispose. При оформлении менялись
только комментарии Core; реализация, объявления и сигнатуры сохранены.

Общие проверки перенесены в Collections/DequeContract: 54 проверки одного
контракта запускаются для каждой реализации через прямой тестовый адаптер.
Существующие проверки ArrayDeque сохранены; кольцевое размещение и рост
проверяются отдельно в Collections/ArrayDeque/ArrayDequeTests.cs.
Всего для двух деков — 109 проверок. Проверяются оба конца, пустой и одиночный
дек, все сочетания концов, очистка и повторное использование, null, дубликаты,
значения по умолчанию, крайние значения int, ссылочная идентичность,
оба входа в перебор, оба Current, вложенные обходы, ранний выход,
Reset, Dispose и инвалидирование во всех состояниях перечислителя.
Для трёх фиксированных seed выполняется 60 000 смешанных операций двух
реализаций со сверкой с LinkedList<int> после каждого шага. Внутренние
инварианты хранилищ проверяются существующими тестами списков.

Существующий единственный Laboratory-факт обновлён: он демонстрирует оба
дека на одинаковых входных данных и сверяет состояния с LinkedList<int>.
Показаны все операции, ошибки и перебор, очистка и повторное использование,
null, дубликаты и ссылочная идентичность. Seed и параметры выводятся
до операций Core; повтор задаётся через DATASTRUCTURES_LAB_SEED.
Демонстрация прошла с новым seed 1324769834 и с заданным seed 12345.
Неверный seed проверен: сценарий завершается явной ошибкой до создания деков.

Locked restore, сборка Release без предупреждений, проверка форматирования
и все 641 обычный тест прошли. Rider проверил все семь затронутых C#-файлов.
Явный Dispose внутри using сохранён для проверки завершения обхода
и повторного освобождения; using гарантирует Dispose при падении Assert.
Аллокации, замыкания, делегаты и boxing ожидаемы в адаптере, проверках
и выводе демонстрации. Предложения использовать collection expression,
method group, инвертировать завершающий if или перенести Show оставлены
без изменения: ToArray обозначает снимок, лямбды явно показывают действия,
if группирует проверки непустого дека, Show расположен перед использованием.
Явный необобщённый foreach сохранён: LINQ Cast может выбрать обобщённый
вход и не проверяет тот же путь исполнения. Делегаты за пределами запуска
не сохраняются.
