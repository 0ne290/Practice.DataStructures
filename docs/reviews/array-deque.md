# Ревью ArrayDeque<T>

## Функциональная корректность и надёжность

Этап завершён. В реализованных автором операциях функциональных ошибок
не обнаружено. По явному запросу автора заполнены участки TODO Codex:
операции чтения и извлечения на пустом деке выбрасывают
InvalidOperationException, реализован перебор через оба интерфейса.

Перечислитель проходит от начала к концу без копии содержимого и фиксирует
версию при создании. Успешные добавления и извлечения с обоих концов,
а также каждый Clear инвалидируют ранее созданные перечислители.
Чтение и отклонённые операции сохраняют их работоспособность.
Изменения обнаруживаются до начала, во время и после конца обхода,
а также после Dispose. Current вне элемента выбрасывает
InvalidOperationException; Dispose завершает обход и допускает повторный
вызов; Reset не поддерживается.

Временный диагностический запуск вне проектов сверил 60 000 смешанных
операций с LinkedList<int> после каждого шага: по 20 000 операций для seed
0, 12345 и 987654321. Дополнительно проверены переход через границу массива
с ростом, опустошение с обоих концов, очистка и повторное использование,
пустые операции, null и ссылочная идентичность, оба интерфейса перебора,
независимость обходов, состояния перечислителя и инвалидирование при
изменениях с сохранением Count. Проверки прошли. Постоянные тесты
и авторский Laboratory-полигон на этом этапе не изменялись.

Locked restore, сборка Release без предупреждений, проверка форматирования
и 532 существующих обычных теста прошли. В обоих проектах packageFolders
указывает на пользовательский NuGet-кэш. Диагностика Rider не выявила
ошибок; подсказки об аллокациях хранилища и перечислителя и возможном
boxing в IEnumerator.Current ожидаемы.

## Архитектура, код и API

Отдельный второй этап завершён. Замечаний, требующих исправления,
по архитектуре, коду и публичному API не обнаружено.

Имя ArrayDeque<T> и имя файла соответствуют словарю: дек с хранением
на массиве. PushFront / PushBack, PopFront / PopBack и PeekFront / PeekBack
явно обозначают выбранный конец и соответствуют наблюдаемому поведению.
Count, IsEmpty, Clear и IEnumerable<T> дополняют базовый профиль.
Перебор идёт от начала к концу. Необоснованных расширений API нет;
Capacity, позиционный доступ, поиск и дополнительный интерфейс
для задачи не требуются.

Композиция с собственным CircularArrayList<T> соответствует постановке:
позиционный API и детали кольцевого размещения скрыты, коллекции BCL
как хранилище не используются. Количество не дублируется. Добавление
на каждом конце сохраняет амортизированное O(1), чтение и извлечение —
O(1), полный обход и очистка — O(n). Рост и сохранение вместимости
при удалении и очистке обеспечиваются внутренним списком.

Собственная версия дека и частный перечислитель согласованы с принятым
решением очередей. Версия меняется после успешной модификации хранилища;
проверка версии предшествует проверке состояния перечислителя.
Обход делегируется списку без копирования элементов. Обёртка добавляет
один объект перечислителя и собственную проверку версии; для текущего
контракта это допустимо. Общая инфраструктура для небольших частных
обёрток не требуется. Методы короткие, ответственность хранилища
и публичных операций разделена, лишних зависимостей нет.

Согласованность имени, словаря, API и поведения проверена. На момент второго
этапа XML-комментариев для сверки не было; их отсутствие до финального
оформления допустимо по правилам практикума. Оба этапа ревью ArrayDeque<T> завершены.
Совместимость с LinkedDeque<T> будет проверена после его реализации.

Повторная диагностика Rider выявила только ожидаемые подсказки
об аллокациях хранилища и перечислителя и возможном boxing в
необобщённом Current. Реализация и публичные объявления при втором
этапе ревью не изменялись.

## Итоговое оформление

XML-комментарии оформлены после обоих этапов и сверены со словарём,
именами и поведением. Указаны операции обоих концов, автоматический рост,
сохранение вместимости, сложность, ошибки, порядок и состояния обхода.
Реализация, публичные объявления и сигнатуры при оформлении не менялись.

Добавлены 46 постоянных проверок в Collections/Deque/ArrayDequeTests.cs
и ArrayDequeEnumerationTests.cs. Проверяются сочетания концов при добавлении
и извлечении, кольцевое размещение с ростом, количество, пустота, ошибки,
очистка и повторное использование, null, дубликаты, крайние значения int
и ссылочная идентичность. Для трёх фиксированных seed выполняется всего
30 000 смешанных операций со сверкой с LinkedList<int> после каждого шага.
Оба интерфейса обхода, вложенные независимые обходы, чтение, состояния Current,
Reset и Dispose проверяются отдельно. Все модификации, включая пару операций
с сохранением Count, проверены до начала, во время, после конца обхода
и после Dispose. Отклонённые операции сохраняют перечислитель;
Clear пустого дека инвалидирует его. Проверки внутреннего хранилища
остаются в существующих тестах CircularArrayList.

Существующий единственный Laboratory-факт заменён полноценной демонстрацией
ArrayDeque<T> со сверкой с LinkedList<int>, Assert и выводом операций и состояний.
Seed и параметры выводятся до операций Core; новый seed выбирается по умолчанию,
повтор поддерживается через DATASTRUCTURES_LAB_SEED. Демонстрация прошла
с новым seed 743957014 и с заданным seed 12345. Неверный seed проверен:
сценарий отклоняет его с явным сообщением.

Locked restore, сборка Release без предупреждений, проверка форматирования
и все 578 обычных тестов прошли. Диагностика Rider выполнена для всех четырёх
изменённых C#-файлов. Явный Dispose внутри using сохранён для проверки состояния
после освобождения и повторного вызова; using гарантирует освобождение при
падении Assert. Аллокации и boxing ожидаемы в проверках и демонстрации.
Предложения инвертировать завершающий if, использовать method group,
collection expression и перенести локальную функцию оставлены без изменения:
ветвление группирует проверки непустого дека, лямбды явно показывают действия,
ToArray обозначает снимок, функция Show расположена перед использованием.
Делегаты не сохраняются за пределами запуска.
