# Ревью LinkedStack<T>

## Функциональная корректность и надёжность

Оба этапа ревью завершены. Операции вершины используют голову собственного
SinglyLinkedList и сохраняют порядок LIFO. Count и IsEmpty соответствуют
хранилищу. Push, Pop и Peek выполняются за O(1), Clear — за O(1).
Пустые Pop и Peek выбрасывают InvalidOperationException без изменения версии.
Удаление узла освобождает его значение и связь с остальной цепочкой.

После разрешённых автором изменений поведение повторно проверено общими
контрактными тестами обеих реализаций стека. Проверяются смешанные операции
с эталонным Stack<int> для двух фиксированных seed, null, дубликаты,
ссылочная идентичность, очистка и повторное использование.

## Архитектура и API

Композиция с собственным списком скрывает узлы и сохраняет ограниченный API
стека. Коллекций BCL как хранилища нет; публичный контракт согласован с ArrayStack.
Push вызывает Values.AddFirst, Peek — Values.TryFirst без создания курсора.
Pop получает удалённое значение через TryRemoveAfter, создавая один курсор.

Перечислитель использует готовый обход списка, вместо самостоятельного движения
курсором и повторного ведения состояний начала и конца. Закрытая обёртка хранит
readonly-перечислитель и признак Dispose. Собственная версия стека нужна для
обнаружения изменений даже после Dispose, когда MoveNext больше не обращается
к внутреннему перечислителю. Dispose завершает обход; повторный Dispose безопасен.
Current и MoveNext проверяют версию до проверки состояния. Reset не поддерживается.

Создание обхода остаётся O(1): выделяются обёртка и перечислитель списка,
вместо прежней пары «перечислитель и курсор». Полный обход — O(n) без копирования.
Это упрощение логики, а не результат измерения скорости. Старый перечислитель
может удерживать прежние узлы после Clear до освобождения ссылки на него.

## Проверки и оформление

XML-комментарии описывают принятое поведение. StackContractTests содержит
общие проверки; ArrayStackTests и LinkedStackTests создают соответствующую
реализацию через тестовый адаптер с прямым отображением операций. Объявления
Core ради тестов не менялись. Все прежние проверки сохранены, дополнительно
проверяются Current пустого перечислителя и изменения стека после Dispose.
Весь прогон содержит 365 обычных тестов, из них 74 — для стеков.

Единственный Laboratory-факт демонстрирует обе реализации на одинаковых данных,
печатает seed и параметры, поддерживает повтор через DATASTRUCTURES_LAB_SEED.

Rider inspections выполнены. Подсказки об аллокациях и boxing оставлены:
перечисление, тестовые адаптеры, делегаты и вывод создают ожидаемые объекты;
делегаты проверок не сохраняются за пределами тестов. Явные Dispose внутри using
проверяют состояние после освобождения и его повторяемость, using обеспечивает
освобождение при падении проверки. Приведение к IEnumerable намеренно проверяет
необобщённый интерфейс; foreach сохранён как предмет проверки.

Restore в locked mode, сборка Release без предупреждений, проверка форматирования
и все 365 обычных тестов прошли. Демонстрация прошла с новым случайным seed
и с заданным seed 12345. Проверки выполнялись через терминал Rider;
packageFolders обоих проектов соответствует пользовательскому NuGet-кэшу.
